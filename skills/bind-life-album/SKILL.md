# 人生造册

把人生票根装帧为一本可独立运行的本地互动古籍。保持基础版完整免费、数据本地优先、视觉规则稳定；不要把个性化设计伪装成基础功能。

## 先确定输入

先确认新藏本的输出目录。只合并询问一次：

- 新藏本的输出目录
- 可选的藏本名称、版次、个人网站、茶钱链接与联络二维码

未提供名称时使用“浮生录”。未提供联络信息时，封面右上角使用古籍宣纸联络签：二维码与“请造册人喝杯茶”只指向茶钱页面；说明文字使用“若欲量身造册，敬请移步访造册人。”；按钮“拜访造册人”只指向个人网站；不重复显示裸网址。默认个人网站为 `https://b-plum.com/`，茶钱页面为 `https://buymeacoffee.com/plum.b`，二维码使用模板内 `public/contact-qr.png`。默认生成本地网站，不询问登录信息，不主动发布。

## 创建新藏本

1. 读取 references/ticket-data-contract.md、references/visual-rules.md 与 references/interaction-rules.md。
2. 运行以下脚本。为每个输入文件或目录重复使用 --ticket；目标目录必须尚不存在，不要覆盖旧藏本。

       node scripts/create-album.mjs --output <新目录> [--title <名称>] [--subtitle <副标题>] [--edition <版次>] [--contact-url <个人网站>] [--contact-label <标题>] [--contact-detail <说明>] [--contact-action-label <按钮文字>] [--support-url <茶钱链接>] [--contact-qr <二维码 PNG>] [--qr-label <二维码说明>]

3. 在生成目录安装依赖并运行 npm run build。
4. 运行结构检查：

       node scripts/validate-album.mjs <生成目录>

5. 启动本地预览并打开页面。只做轻量运行检查；用户未要求浏览器测试时，不代替用户点击或检查视觉细节。
6. 交付本地目录与打开方式。只有用户明确要求“发布”时，才使用可用的网站构建与托管能力发布。

## 保持固定产品规则

- 保留合书开卷和“过去 / 未来”两枚书签。
- 过去篇根据可用空间自然排列：宽敞时每半页三张，窄屏或低矮窗口自动改为两张；当当前票根数量不足以填满半页时，以票根组作为整体在可用高度方向居中，尤其是两张票时不得贴近页面顶部或底部；票根之间保持均匀留白，完整显示且不得重叠、裁切。
- 移动端过去篇使用横向翻页与吸附效果，不把多页纵向堆叠。
- 未来先显示完整空镜，滚动后渐显并在中央吸附；票根保持原始比例，不裁切、不变形。以普通票短边为响应式基准，长宽比达到 2:1 以上的细长票，其长边固定为普通票短边的 2 倍，短边按原比例反推；仅在超出安全宽高时整张等比例缩小。未来票尺寸容器是唯一尺寸来源，导入票面必须移除通用票面的固定横向 `aspect-ratio`，容器、票面与图片不得互相溢出。
- 仅使用票根原始 PNG；不要重绘、裁切、加网页时间标签。
- 置入票根时核对票种与票形：过去只接受幕间长票和胶片齿票，未来接受全部三种；JSON 声明必须与 PNG 尺寸一致。仅有旧式 PNG 时可按票号与尺寸识别，过去竖票仍须拒绝。
- 使用 IndexedDB 保存用户后来拖入的票根与默认票根显示状态，并明确“仅保存在此浏览器”。
- “清空票根”清除本地票根并隐藏网站自带票根；确认后可用“恢复默认票根”重新显示网站自带票根，但不恢复已清除的本地票根。
- 清空、恢复、置入成功或失败等状态提示只短暂显示，默认约 4.2 秒后自动消失。
- 中文使用令东齐伋复刻体；数字与英文使用思源宋体。
- 古籍宣纸联络签只出现在合书首页：二维码及点击二维码都在新页打开茶钱页面，独立按钮在新页打开个人网站；两种用途分区呈现，不显示裸网址、不重复文案。二维码必须完整、等比例且可扫描，不得重绘或覆盖定位点。
- 不添加账号、云同步、站内支付结算、广告或预测性显化内容；茶钱入口只作为可选外部链接，不弹窗、不追踪、不限制免费功能。

## 处理定制请求

基础版只调整名称、副标题、版次、主人落款和联络信息。用户要求重新设计封面、世界观、主题、动画或布局时，先明确这是个人定制范围，再按用户授权修改生成的网站；不要改写本 Skill 的基础模板规则。

## 验收

完成前读取并逐项核对 references/acceptance-checklist.md。脚本和构建任一失败时，修复后重新验证，不交付半成品。
