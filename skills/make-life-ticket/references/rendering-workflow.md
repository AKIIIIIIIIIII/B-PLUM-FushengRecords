# 出票与渲染流程

在用户明确回复“出票”后读取本文件。先选择图像来源，再用确定性模板叠加所有文字和票券结构。不得把整张带文字票根交给图像模型生成。

## 总顺序

1. 整理票种、标题、时间、地点、可选记录、画面构想与印章装饰；印章可以由用户指定，也可以先选择“随机”。
2. 如果印章为“随机”，先从三款中选定具体款式；返回一份所有项目均已确定的完整出票单，不保留未解析的“随机”。
3. 继续等待用户根据这份确定信息明确回复“出票”；“继续”“可以”“就这样”不能触发渲染。
4. 收到“出票”后进入精致出票，生成票根编号并确认输出目录中不存在同名文件；把已确认的具体印章写入 `stampStyle`。
5. 按票种选择或复用相容的 `shapeStyle`，再匹配 `layoutStyle`；往昔只允许两种长票，未来允许全部三种票形。
6. 先依据最终票形锁定主图的目标画幅与主体安全区，再按下述优先级取得无文字主画面：首轮 AI 生成 → 仅一次非品牌化改写后的 AI 重试 → 本地程序化画面。前两步都没有得到可用图片之前，不得调用无 `--image` 的渲染器；不得先生成任意比例的图，再依赖居中硬裁切。
7. 从视觉元素、场景和地点中确定一个事件关键词；独立生成无文字、透明背景的事件涂鸦 PNG，失败时以中性描述重试一次，仍失败则标记为 `skipped`。根据票型载入无文字生成式纸张底胚，以本地精确模板裁切票形、绘制朱红结构、分栏和全部票面文字，再叠加事件涂鸦与已锁定的状态印章。
8. 导出透明背景 PNG 与同名 JSON，检查尺寸、文字、印章、透明外沿和数据一致性后交付。

默认将文件写入当前任务的可写工作目录；用户指定其他可写位置时服从用户。不要覆盖已有文件。

## 图像来源优先级

### 用户提供照片

优先使用照片作为人物或场景依据：

- 如果当前环境具有图像编辑或生成能力，将照片转化为复古寓言卡绘式插画。
- 如果没有该能力，使用本地裁切、双色调、网点、纸纹和墨线化处理，保留照片内容但呈现复古印刷效果。
- 不把原始照片复制进 Skill，不在 JSON 中保存照片路径或二进制内容。
- 在 JSON 中写入 `source: "uploaded"` 与 `referenceUsed: true`。

### 没有照片且可生成图像

根据用户确认的画面构想生成原创无文字插画。在 JSON 中写入 `source: "generated"`。

### 没有图像工具或生成失败

图像工具不可用时，立即改用程序化象征画面继续出票，不要求用户配置 API Key，不只输出提示词，也不终止流程。首轮生成因安全审核、带字／乱码、签名／水印或主体不完整而失败时，必须先进行一次 AI 重试：保留事件、地点、动作、情绪与安全区，移除或改写可能触发审核的专名、品牌名和角色名，改用中性的视觉描述。例如把“某品牌角色玩偶”改为“相应颜色与特征的卡通玩偶”，但不得声称仍在复刻该品牌角色。重试不得超过一次；只有第二次 AI 生成仍失败后，才将 `image.source` 改为 `procedural` 并调用本地画面。

程序化出票时，在 JSON 中写入 `source: "procedural"`，并仍保留原始绘图提示词，方便以后重新生成。

Skill 不包含开发者 API Key，不调用由 Skill 作者代付的远程服务。只使用当前运行环境已经提供给使用者的图像能力。

## 生成式画面

只生成主画面，不生成完整票面。根据当次内容组装提示词：

> 创作一幅原创的当代编辑插画，用于高级收藏票根的主画面。人物自然、安静、有真实瞬间感；使用细而干净的深炭黑墨线、低饱和平涂色块与少量局部排线。避免粗黑轮廓、夸张表情、漫画式强动作、密集复古广告半点和泛黄滤镜。配色以骨白、深墨绿／深炭黑为基底，只使用一到两个低饱和辅助色，例如石油蓝、灰青或烟陶土；不使用金色、霓虹、强光晕、塑料高光或 3D。纸张感只体现为轻微无涂布纸颗粒与极淡油墨吸收边缘，主图应像印在纸上但不能显旧、脏或颗粒过密。背景信息简洁，为人物、关键动作和物件保留呼吸空间。严格遵循当次票形指定的目标画幅与主体安全区，人物的头部、上身、手部和关键叙事物件必须完整位于安全区内，不能被最终裁切。画面中不得出现任何文字、字母、汉字、数字、牌名、牌号、条码、商标、水印、现成塔罗牌构图或可识别品牌。

根据票形在调用图像生成前指定画幅与安全区：

- `stage-triptych`（`intermission-stub`、`film-edge`）：主图目标为近方形到轻微竖向，约 `5:4`；人物完整上身、手部及关键道具放在画面中央 70% 宽度与中央 78% 高度内。不得把完整人物放到画面底部再依赖裁切。
- `chapter-poster`（`chapter-pass`）：主图目标为横向电影画幅，约 `3:1`；人物必须是完整上身或清晰剪影，连同手部、旅行箱等关键道具置于中央 60% 宽度和中央 70% 高度内。背景可延展到两侧；不得生成竖版全身肖像后再裁成横条。

如果生成工具不能直接指定尺寸，也必须在提示词中写明目标横／竖画幅及安全区，并将其作为构图硬约束。生成结果预览中若主体、关键动作或关键物件不完整，重试一次；仍不合格则改用程序化画面，不能交给渲染器靠裁切猜测主体。

如果工具返回的画面带有文字、乱码、签名或水印，重试一次并强化无文字要求；仍失败时转为程序化画面。

如果首轮被安全审核拦截，或专名、品牌名、角色名可能是拦截原因，也只允许一次语义保留的非品牌化改写重试；不要把失败原因说成确定事实，除非工具实际返回了该原因。

## 照片处理

使用照片前先确认它是用户提供且希望用于本次票根的图片。只处理本次任务需要的图片。

有图像编辑能力时：

- 保留关键面部、发型、衣着或场景特征。
- 将照片转化成原创墨线与平涂插画，不改变用户指定的人物关系和事件。
- 不添加用户没有要求的其他可识别人物。

只有本地处理能力时：

- 按画面区比例居中裁切，优先保留人物与关键物件。
- 使用低饱和双色调或有限色阶。
- 叠加轻微网点、纸纹与边缘墨线，不严重磨损照片。
- 不对照片内容进行生成式补画。

## 程序化画面

使用本地 SVG 或绘图脚本组合原创、基础的几何和线描元素：

- 从画面构想中选择 3–5 个可视化元素。
- 优先调用与已识别事件对应的本地场景模块。例如识别到“娃娃机／机械爪／玩偶”时，绘制娃娃机、机械爪、取物口和通用黄色护目镜玩偶，而不是回退到无关的山景；没有对应模块时再使用通用象征构图。
- 优先使用太阳、月亮、道路、门、窗、山、水、云、植物、建筑轮廓和简单人物剪影等通用形状，但只采用与用户内容相关的元素。
- 使用有限色板、墨线、排线、网点和纸纹形成复古寓言卡质感。
- 不下载外部素材，不使用现成塔罗图案或第三方图标包。
- 即使无法准确画出复杂对象，也要通过抽象构图表达事件、地点和情绪。

## 确定性排版

无论主画面来自何处，都使用本地渲染完成：

- 票形轮廓、缺口、撕票线和透明外沿
- 画面裁切
- 产品名、票种、标题、时间、地点、票号、日期与状态
- 用户提供时的一句话记录
- 在正常预览尺寸下清楚可见的暖米黄纸张纤维、连续半点、油墨颗粒与装饰线；以低对比环境阴影和浅压痕表现票形外沿、撕票结构与内框的纸张层次；主画面须使用同一套印刷质感融合，不得呈现光面后贴照片感
- 出票前先在白色背景上预览成品：确认朱红色旧版式的所有结构与位置未改变，同时确认短纤维、纸浆云纹、外沿落影、撕票线压印与主图框压印在正常预览尺寸下都可见。透明 PNG 仍为正式交付文件。

三种票型均有一张无文字的生成式纸张底胚：`intermission-stub`、`film-edge`、`chapter-pass`。底胚只提供棉纸纤维、纸浆云纹、厚纸边缘与压印的物理观感；**不得**让图像模型承担文字、朱红排版或几何位置。实际轮廓仍使用本地模板遮罩，保证幕间副券、胶片齿孔和章节切角准确不漂移。

不要要求图像模型生成中文票面。所有中文统一使用 Skill 内置的令东齐伋体；因齐伋体没有拉丁字母和阿拉伯数字，英文、日期数字与票号统一使用内置思源宋体。不要在出票时从网络临时下载字体。限制文字区域并主动换行或缩小，禁止裁断、溢出或互相覆盖。时间不得压过标题，也不得明显大于地点；地点、记录和凭证信息须在缩略预览中可读。

在票面渲染层把 `，` 与 `,` 替换为 `、`，但保持 JSON 原文不变；不要替换句号或改写其他内容。

票券结构必须独立成立：即使暂时移除主画面，仍应通过不对称网格、字号反差、编号轨道、双线框与单一强调色看起来像完成的收藏票，而不是套入图片的表单模板。

## 印章装饰

本环节发生在精致出票与任何渲染之前。先提供“花笺长印”“白文方印”“残环圆印”与“随机”；用户保留“随机”时，也要在返回最终出票单前解析成具体款式并标注“随机结果”。用户根据这份确定的出票单明确回复“出票”后，才能进入精致出票。

状态章使用 `assets/status-stamps/` 中已经带字的透明 PNG，不能再用脚本绘制双圆圈或在运行时重排状态文字。根据 `design.stampStyle` 与 `status` 选择对应资产：

- `floral-slip`：花笺长印
- `negative-square`：白文方印
- `broken-ring`：残环圆印
- `ended` 使用文件名后缀 `-ended`，`ordered` 使用 `-ordered`

未设置 `stampStyle` 时按 `ticketNumber` 稳定随机并写回 JSON；未知枚举、缺失文件、无透明通道或空白资产都必须停止渲染并明确报错，不能退回旧圆章。按各款纵横比缩放进既有状态区域，保持完整图形且不得遮挡标题、撕票线或凭证信息。

## 事件涂鸦

事件涂鸦在用户确认“出票”后独立于主图生成，不能由本地脚本临时画线或从预制图库匹配。先从用户提供的 `visualElements` 中选取第一个具象关键词；若没有，再从场景或地点中提取一个具象关键词。将结果写入 `design.eventDoodle.keyword`，用户要求不添加时写 `status: "none"`。

使用图像生成能力制作一张方形透明 PNG：以简笔手绘图形为主，颜色从当次主图与票面气质中提取一至两种协调色；线条要像随手画后盖印的断续墨迹，带轻微边缘不均和压印感；不含文字、字母、数字、品牌、角色复刻、签名或水印。四周保留透明安全边。首轮失败时仅以更中性的视觉描述重试一次；第二次失败时写 `status: "skipped"`，继续出票，不用程序化图标替代。

生成成功时写 `style: "broken-ink-doodle"`、`status: "generated"`；长票使用 `placement: "place-record-side"`，方票使用 `placement: "place-side"`。PNG 只作为当次渲染的临时输入，不写入 JSON，也不作为第三个正式交付文件。渲染器接收 `--doodle <png>`，必须验证其透明通道和非空内容；长票将其置于地点／记录右侧、朱红引导线下方，方票置于地点信息右侧，空间不足时缩小一次，仍不足则跳过并将状态更新为 `skipped`。

## 精致出票

用户明确回复“出票”后才进入本阶段。依次取得或生成无文字主画面、独立生成事件涂鸦透明 PNG、完成确定性票面排版、直接叠加事件涂鸦与已锁定的带字状态印章、生成白底检查预览，再导出正式透明 PNG 与同名 JSON。印章与涂鸦选择都是精致出票的输入，不能在渲染完成后临时补选。

“精致出票”指使用既定纸张、版式、插画与印章资产完成最终成品，不把整张票交给图像模型重绘，也不代表自动执行额外的 AI 润色。

## 运行本地渲染器

准备好已确认的 JSON 后，从 Skill 目录运行：

```bash
python3 scripts/render_ticket.py --input <票根.json> --output-dir <输出目录>
```

取得首轮或重试后的 AI 主图、或用户照片时追加：

```bash
--image <图片路径> --require-image
```

事件涂鸦生成成功时追加：

```bash
--doodle <透明 PNG 路径>
```

用户明确指定印章款式时可追加：

```bash
--stamp-style <floral-slip|negative-square|broken-ring>
```

通常让脚本读取 JSON 中的 `design.shapeStyle` 与 `design.stampStyle`。只有用户明确选择或重新随机时，才使用 `--shape` 或 `--stamp-style` 覆盖。脚本会补齐并保存最终 `design`；当仍处于 AI 主图尝试阶段，必须传入 `--require-image`，使缺失主图明确失败而非静默降级。只有首轮与重试均失败、流程已将 `image.source` 设为 `procedural` 时，才不传 `--image` 以绘制本地备用画面；涂鸦被标为 `generated` 时必须传入 `--doodle`，被标为 `skipped` 或 `none` 时不得传入。

渲染器需要 Pillow。优先使用当前环境或工作区已提供且包含 Pillow 的 Python；不要为了运行脚本擅自联网安装依赖。

## 交付与失败处理

默认只交付：

1. `{ticketNumber}.png`
2. `{ticketNumber}.json`

SVG、临时裁切图和中间背景只作为工作文件，不向用户列为正式产物。完成后展示 PNG，并提供 PNG 与 JSON 的可访问文件链接。

如果 AI 图像生成失败但程序化出票成功，简短说明已使用复古象征画面完成，不把它描述为错误票。如果最终 PNG 或 JSON 任一缺失、为空、尺寸错误或无法打开，不得宣称出票完成；修复或重新渲染后再交付。
