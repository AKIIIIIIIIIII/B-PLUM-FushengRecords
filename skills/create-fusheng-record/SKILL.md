# 生成浮生录

这是协调入口，不复制其他 Skill 的详细规则。默认只生成本地藏本，不覆盖旧目录、不自动发布。

## 选择票根来源

- 用户提供票根、指定当前对话已生成票根或明确要求先制作个人票根时，使用个人票根分支，不混入样票。
- 用户只说“生成一整套浮生录”等裸请求且没有指定票根来源时，默认准备过去 5 张、未来 5 张虚构样票；不再让用户先选择票根来源。

不要直接创建空册后宣称“浮生录完成”；完成品必须至少收录一张票。

## 默认样票的总确认

裸请求发生后，第一次只展示提醒，不调用图像工具、不运行样票脚本、不创建目录：

> 将先生成过去 5 张、未来 5 张完全虚构的演示票，再建立新的本地《浮生录》并自动收录。批量生成可能耗时；不会覆盖已有目录，也不会自动发布。以后可在网页中清空样票，再制作并收录自己的票根。
>
> 请提供一个尚不存在的新藏本输出目录；如需修改藏本名称、样票数量或其他造册配置，也请一并说明。确认无误后，请准确回复“确认生成”。

- 必须同时得到准确短语“确认生成”和一个尚不存在的输出目录，才能执行；“可以”“继续”“确定”等表达不能代替。
- 用户修改数量、名称或其他配置时，按新配置重新展示最终提醒并继续等待“确认生成”。默认数量仍为过去 5 张、未来 5 张，总数至少一张；仅在用户指定时固定随机种子。
- 回复缺少确认短语、目录或目录已经存在时，只补问缺项，不执行任何生成步骤。
- 这次总确认同时授权协调模式下的批量样票渲染；后续不再要求第二次回复“出票”。

## 协调顺序

### 已有票根

1. 使用 `../bind-life-album` 创建空册。
2. 使用 `../collect-life-tickets` 收录票根。
3. 构建、验证并启动本地预览。

### 制作个人票根

1. 按 `../make-life-ticket` 逐张完成确认和出票。
2. 用户可以继续制作；只有用户说“收录成册”后才创建空册。
3. 使用 `../collect-life-tickets` 一次收录本轮全部成功票根。
4. 构建、验证并预览。

### 默认样票一键生成

取得总确认后自动连续执行：

1. 以协调准备模式调用 `../implant-sample-tickets`，将样票 PNG 与 JSON 写入任务专用临时目录；展示出票摘要与进度，但不再暂停确认，也不在此阶段收录。
2. 若一张完整票都没有生成，停止且不创建空册；部分失败时保留失败信息，使用全部成功票继续。
3. 以延后收尾模式调用 `../bind-life-album` 创建无票根新册并安装依赖，不预览中间空册。
4. 使用 `../collect-life-tickets` 一次收录临时目录中的全部完整票；由该 Skill 执行最终构建和结构验证。
5. 验证通过后启动本地预览并汇总成功数、程序化主图数、跳过涂鸦数和失败项；此后可清理临时副本。任一步失败时保留临时票根，方便重试。

任何分支失败时保留已生成的票根文件，报告失败阶段；不要删除或覆盖用户旧藏本，不自动发布。
